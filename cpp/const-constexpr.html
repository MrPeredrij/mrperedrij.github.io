const и constexpr

const обещает, что объект не будут менять через это имя. constexpr идёт дальше: значение (или результат функции) должно быть доступно на этапе компиляции, если аргументы тоже константны.

const для объектов и указателей

Правила те же, что в C, и так же легко запутаться в месте const:

ЗаписьСмысл
const int n = 5; / int const n = 5;неизменяемое целое
const int *pуказатель на константу: *p менять нельзя, p можно
int *const pконстантный указатель: адрес не меняется, значение по адресу можно
const int *const pнельзя ни то, ни другое

Константные методы

Метод с const после списка параметров не меняет объект и может вызываться у константного объекта и через const T&. Внутри такого метода this имеет тип const T *.

constexpr

Переменная constexpr всегда инициализируется константным выражением и неявно const. Функция constexpr может вызываться и в обычном коде, и там, где нужна константа компиляции (размер массива, аргумент шаблона, static_assert). В C++14/17 тело такой функции может содержать обычные локальные переменные и циклы — лишь бы при константных аргументах результат считался на этапе компиляции.

Чем заменить макрос

ИнструментКогда использовать
#define PI 3.14В C++ почти никогда: нет области видимости и типа
const double pi = 3.14;Значение известно, но не обязано быть константой компиляции во всех контекстах
constexpr double pi = 3.141592653589793;Предпочтительный способ для констант
enum { N = 16 };Целые константы, особенно в старом коде
C++20 добавил consteval (функция только для этапа компиляции) и constinit (статическая инициализация без обязательной константности потом). Для C++17 достаточно уверенно пользоваться const и constexpr.
